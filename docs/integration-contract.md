## Public inputs and capabilities

`cedra:signAndSubmitTransaction` implements wallet-standard 0.5.1: `{payload,maxGasAmount?,gasUnitPrice?}`. It never accepts SDK `{data,options}` under that standard name. Unknown required fields, mixed wrappers, and conflicting aliases are invalid before dispatch.

The explicit `inferenco:transactionSubmission` feature version 1.0.0 has contractVersion 1 and `signAndSubmitTransaction(input,{onInvocationPrepared?})`, returning the standard Approved/Rejected response. Its canonical input is `{contractVersion:1,data:{function,typeArguments,functionArguments},options:{maxGasAmount?,gasUnitPrice?,sequenceNumber?,expireTimestamp?},sender?,chainId?}`. The class API separately documents SDK convenience `{data,options}` and unwrapped entry-function input. Canonical input and supported sign-only exact BCS are distinct. Unsupported raw submit, fee payer, secondary signer, gas-token or other required semantics must fail before dispatch rather than be dropped.

The complete submission feature belongs to the adapter: it includes the awaited invocation hook, opaque non-dispatch proof and public original-outcome recovery. Native Desk/mobile wallet-standard registrations expose their implemented standard subset; their raw injected providers separately expose the v1 invocation metadata/read API described below. A native registration must not advertise the custom feature with only a transaction-forwarding wrapper. Hosted applications that require the complete feature must retain an adapter registration alongside the native standard entry and select by actual capabilities; wallet names alone do not prove support.

Restrictions are exact unsigned u64 decimal strings; chainId is an unsigned u8 integer. Accept explicit absolute aliases expireTimestamp, expirationTimestamp, expiration_timestamp_secs and expirationTimestampSecs only when equal; accept expirationSecondsFromNow as positive u32 only without any absolute expiry. sequenceNumber also accepts SDK accountSequenceNumber as an equal alias. Nested/top-level fields merge individually, equal duplicates are allowed, conflicts fail. Sender is a canonical 32-byte lowercase hex address and must match the approved signer. The requested network/chain must match the approved session. networkOverride is a requirement check, not an instruction that silently changes the wallet; fullnodeUrl is retained for API compatibility but is not read by the signing transports. The exported getSdkNetwork and signAndSubmitWithSdk helpers accept an explicit fullnodeUrl; configuring it never redirects wallet signing or changes the approved network.

A peer explicitly advertises `integrationContractVersion:1` and `capabilities:{transactionRestrictions:true,messageProfile:"cedra:message:v1",completeResults:true,durableInvocationLookup:true}` (durable lookup applies to the implemented Desktop bridge and native embedded providers; external mobile uses its existing relay recovery). Unknown versions fail. Legacy peers may receive only their genuinely supported legacy/standard subset; required v1 restrictions are rejected if capability cannot be established. New adapters do not infer capabilities from wallet names or installed source.

## Bounded lossless wire values

Support null, booleans, strings, safe integer numbers, nonnegative bigint up to u256, Uint8Array, dense arrays and plain own data-property objects. Encode bigint as exact decimal strings and Uint8Array as arrays of u8; receiving parsers interpret arguments using ABI types, never floating point. No generic class/toJSON/getter coercion. Explicit AccountAddress conversion is permitted at the typed address boundary. Reject undefined values in arrays, holes, symbols, functions, unsafe/fractional/nonfinite numbers, unsupported prototypes, accessor properties, cycles and dangerous object keys. Optional undefined object properties are omitted before wire encoding; they express no requirement. Object keys must be printable ASCII. Maximum depth 32, maximum visited values 10000, maximum encoded UTF-8 JSON 262144 bytes. Bounds apply at real admission and preparation, not just fixtures.

Canonical JSON recursively sorts object keys lexicographically (ASCII), uses compact JSON with JSON string escaping, and preserves array order. All integers on signed restriction fields use their specified normalized representation. Native constructors in fixtures exercise bigint/Uint8Array before encoding.

## Clock and expiry

The caller UTC clock is the authority for converting relative expiry into an absolute expiry at adapter preparation. Capture floor(Date.now()/1000) once; add the exact relative u32 and store the absolute u64. A directly admitted legacy request resolves relative expiry once at native admission. Never resolve again during review, delay, reconnect or recovery. Wallet checks its UTC clock immediately before signing; now >= expiry rejects. There is no grace period that extends the approved lifetime. Clock disagreement may reject conservatively and requires correcting the clock, never refreshing the approved timestamp. Default wallet expiry applies only if no expiry was required.

## Message profile

`profile:"cedra:message:v1"` signs UTF-8 of LF-joined lines, with no final LF:

1. `CEDRA`
2. `address: <canonical approved address>` only if input.address === true
3. `application: <authenticated caller origin>` only if input.application === true
4. `chainId: <approved chainId>` only if input.chainId === true
5. `message: <exact input.message>`
6. `nonce: <exact input.nonce>`

Message and nonce must be strings, inclusion flags booleans; nonce and context contain no CR/LF, message may contain newlines. Missing nonce or arbitrary value coercion is invalid. The complete result contains profile, prefix CEDRA, message, nonce, fullMessage, signerAddress, publicKey and 64-byte Ed25519 signature hex on the wire. Signed address/application/chainId fields exist only if requested. Adapter returns an SDK Ed25519Signature and verifies exact requested preimage/context/signer rather than trusting returned fullMessage. Legacy compatibility is capability-bound and verified from the inspected producers: old Desktop raw signs exactly the requested challenge containing the nonempty nonce; old external mobile signs the exact positional `CEDRA\n\n<original address spelling>\n<nonce>\n\n<message>` preimage. Only requests with all context inclusion flags false may use those routes. Adapter verifies actual bytes and the approved key before exposing explicit `raw` / `cedra:legacy:v0`; unsigned old application/chain echoes are discarded. New v1 requests cannot downgrade. Old embedded APTOS/backslash-token envelopes are explicitly unsupported. Verified legacy creator-challenge authentication remains supported until separately retired.

Only an exact explicit Rejected outcome means user decline. HTTP401, text containing reject, signing exceptions, malformed approval, timeout and transport errors do not mean decline. Operational failures remain failures or unknown execution as appropriate. A submitted hash is identity, not confirmed chain success.

## Invocation and immutable request commitment

Before any signing/submission dispatch the adapter persists a stable invocation identity and canonical request commitment, then awaits the caller's onInvocationPrepared hook. The descriptor includes invocationId, origin, transport, original sessionId, address, network, chainId, method and requestCommitment. Commitment is lowercase SHA256 hex of canonical JSON `{contractVersion:1,method,scope:{origin,accountAddress,network,chainId},payload}`. It excludes the commitment itself, credentials and sessionId. Original session binding is stored separately; scope remains immutable during authorized renewal. The canonical approved address is used in scope. The same commitment binds encoding, admission, results and recovery.

Desktop existing POST routes add contractVersion, invocationId and requestCommitment beside normalized method input. Admission atomically stores invocation->requestId, commitment, full scope and input before acceptance. Same invocation/same content returns original receipt; any substitution fails. GET `/invocation/<id>` with authenticated sessionId, origin, accountAddress, network, chainId, method and requestCommitment is read-only. It returns contractVersion, invocationId, requestId, requestCommitment, originalSessionId and scope. New authorized sessions may read only matching origin/account/network/chain/method; knowledge of IDs alone is insufficient.

Mobile retains the existing relay clientInvocationId/encryptedRequest envelope. Version1 decrypted plaintext is `{contractVersion:1,requestCommitment,scope,payload}`; method and invocation identity are in the authenticated outer request. Wallet recomputes the commitment before execution. Preserve the existing durable started->ready->delivered journal, exact encrypted result redelivery and invocation lookup. No new relay semantics are assumed without source evidence.

`isNotInvoked(error,invocation)` on the explicit public feature accepts only adapter-owned, invocationId+commitment-bound evidence created before dispatch. Public strings, numeric codes and echoed markers are never proof. Once any transport dispatch begins, exceptions/lost receipts remain unknown. A generic wallet throw remains conservative. A lost creation receipt is recovered by authenticated original-invocation lookup, never by repeating creation.

Native embedded providers receive invocation metadata separately from transaction options: `provider.signMessage(payload, metadata)`, `provider.signTransaction(payload, metadata)` and `provider.signAndSubmitTransaction(payload, metadata)`, where metadata is `{contractVersion:1,invocationId,requestCommitment,scope}`. The native host validates the actual WebView origin and current account/network grant before admitting the operation in its existing outcome store. `provider.readInvocation(invocationId,requestCommitment)` is read-only and returns `{contractVersion,invocationId,requestCommitment,scope,method,status,payload?}`. Native session identity remains separate from the adapter's local correlation identity. A new authorized WebView session can read only the same immutable scope. Public adapter recovery validates the original commitment and complete result, then persists it before returning; it never invokes signing. Legacy sign-only authenticator-only responses are retained for compatibility and do not claim complete durable result support.

## Durable results and execution

Extend existing stores, preserve old rows. Desktop GET `/read-result/<requestId>` uses the existing adapter authorized-read scope and returns requestId,new sessionId,scope,status,payload,finalizedAt,contractVersion,requestCommitment and invocationId. Complete message output, exact sign-only BCS/authenticator and submit hash are retained. Pending, unknown, unavailable and legacy incomplete records are explicit and cannot fabricate approved fields. Acknowledgment/archive changes retention/delivery only, never authorizes execution. Desk retains terminal acknowledged results and associated admission/index/payload/signed bytes for 30 days after acknowledgement, then prunes them atomically. Original lookup after pruning is unknown and cannot authorize recreation. Queued, claimed, signed, uncertain and unacknowledged work is not removed by that terminal-retention rule. Store maintenance is throttled to avoid a full scan for every polling request.

Desk lifecycle is durably queued->claimed->signed/submitting->terminal. Cancellation/expiry wins only before execution claim; after claim retain uncertain/pending execution and any late identity/result. Persist scoped transaction hash and signed BCS before broadcast; storage failure prevents broadcast. Restart never recreates or re-signs an unresolved operation. Reconcile the existing transaction identity, then verify canonical receipt/effects in the dApp. Never infer successful application effects solely from the presence of a hash.

Original execution evidence and retention acknowledgement: pending/unknown public recovery outcomes may contain `transactionHash`, a strict 32-byte hex identity authenticated against the original invocation, commitment and scope. This evidence is persisted independently of terminal results and survives a later wallet outage. It is not an approval or a confirmed chain receipt; applications must verify the original receipt/effects and must never replace the submission. A conflicting later hash is rejected. Desktop recovery applies the same message signature/preimage and exact-BCS validation and SDK hydration before both first return and local replay.

For retained v1 Desktop terminal results, public acknowledgement uses the current authorized account/network session and awaits the wallet's `/acknowledge-result/<requestId>` response before hiding local delivery. A failed acknowledgement leaves the result active for retry. Native providers can expose `acknowledgeInvocation(invocationId, requestCommitment)` with the same scoped acknowledged envelope; older peers without v1 durable recovery or native acknowledgement support retain local-only acknowledgement. Neither operation acknowledges uncertain execution or authorizes signing. Independently reconciled uncertain operations use the existing archive API.

Admission records retain whether the original Desktop/native peer required remote retention acknowledgement. A disappeared or downgraded peer cannot clear a recorded obligation: local delivery remains active until the matching peer acknowledges. Historical Desktop rows with invocation/commitment but no capability marker remain conservatively retryable; only explicit original legacy capability permits local-only acknowledgement. Historical native rows require a present matching-scope peer before treating its missing optional API as legacy support. Already acknowledged results remain idempotent without a wallet connection.

Injected signing rechecks provider identity, contract version, live account/key and network after the awaited preparation hook; account/network events during those reads also invalidate preparation. A changed scope produces invocation-bound non-dispatch. An explicitly requested v1 message requires an explicitly labelled complete v1 result; verified legacy message handling remains unchanged.

Browser retention deletes eligible acknowledged/archived external request records and their exactly linked invocation payloads in one transaction, while preserving active, uncertain and unlinked work. Recovery uses direct invocation/opaque-handle keys and the existing scope index; bare request IDs retain a cursor fallback to detect ambiguity across sessions. The IndexedDB version remains 1 so older adapter tabs retain access.

Legacy injected sign-only requests with networkOverride also reread the live provider network immediately before signing and reject provider/version or observed scope changes across that read. This check does not require a new account() method or change supported legacy authenticator-only results.
